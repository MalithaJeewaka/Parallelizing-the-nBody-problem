# OpenMP N-Body Simulation Guide

This folder contains the **OpenMP** implementation of the N-Body simulation, which uses shared-memory multithreading to speed up the gravitational calculations.

## ⚡ How It Works

The core code is located in `openMP_nBody.c`. OpenMP parallelizes the application by utilizing compiler directives, specifically `#pragma omp parallel for`.

1. **Loop Parallelization**: 
   The outer loop that iterates over each particle to calculate forces is annotated with `#pragma omp parallel for`. The compiler automatically divides the total $N$ iterations (particles) among the available CPU threads. For example, if there are 10,000 particles and 4 threads, each thread handles 2,500 particles simultaneously.
   
2. **Thread Safety**:
   Variables like `Fx`, `Fy`, and `Fz` are declared *inside* the parallel loop. This is critical because it makes them "private" to each thread. Each thread has its own local copy, preventing race conditions (threads overwriting each other's work).

3. **Position Integration**:
   The second loop, which updates the positions of the particles based on their new velocities, is also parallelized since updating one particle's position is completely independent of the others.

4. **Dynamic Thread Allocation**:
   The code uses `omp_set_num_threads(numThreads)` to dynamically set how many cores the simulation should utilize, based on the command-line argument. High-precision timing is handled using `omp_get_wtime()`.

## 🚀 How to Run

To run the simulation, you must compile it with the `-fopenmp` flag and then execute it by passing the number of particles and the number of threads. You must run this inside a Linux environment (like WSL).

**1. Generate the initial particles:**
```bash
gcc -o paramGen particle_production.c
./paramGen 10000
```

**2. Compile the OpenMP simulation:**
```bash
gcc -o openMP_version openMP_nBody.c -lm -fopenmp
```

**3. Run the simulation (e.g., with 4 threads):**
```bash
OMP_NUM_THREADS=4 ./openMP_version 10000 4
```
*Note: The environment variable `OMP_NUM_THREADS=4` tells the system to allocate 4 threads, matching the command-line argument.*

## 🔍 How to See the Results

After running the simulation, it outputs a binary file named `openmp_output.txt` in this folder. Binary files are optimized for performance and cannot be read directly in a text editor.

To read and verify the output, you must decode it using the `reader` utility located in the root directory:

**1. Navigate back to the root directory:**
```bash
cd ..
```

**2. Copy the binary output so the reader can find it:**
```bash
cp opneMP/openmp_output.txt particles.txt
```

**3. Compile and run the reader program:**
```bash
gcc -o reader read.c
./reader
```

**4. View the human-readable text file:**
The program converts the binary data into `readable_output.txt`. You can view the first few lines with:
```bash
head -n 12 readable_output.txt
```
This file contains the final Mass, Position, and Velocity for each particle. To mathematically prove the OpenMP version is correct, you can use the `diff` command to compare this file against the output generated by the Sequential version.
